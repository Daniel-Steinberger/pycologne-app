## Dokumentation von Projekten

Erstes Thema: Dokumentation von Projekten, bekannte Probleme beim Einstieg für
neue Mitarbeiter und Kollegen.

- Oft werden Projekte schlecht dokumentiert, und neue Kollegen werden als "wo
  du gerade dabei bist" zur Dokumentation herangezogen.
- Tests sind gut für die Dokumentation, da sie schnell Probleme/Unklarheiten in
  der API aufzeigen.
- Tests sind ebenfalls gute Beispiele zur Verwendung einer API.

Zu Tests:

- Unit-Tests vs. Integrationstests
- hypothesis-Modul als Generator für zufällige Daten und zum Finden von
  Randfällen: https://hypothesis.readthedocs.io/en/latest/
- Testdaten generieren mit https://faker.readthedocs.io/en/latest/

## Einstieg mit Python

Zweites Thema: Einstieg mit Python, wie fange ich mit Python an? Viele der
neuen Teilnehmenden haben spontan über Meetup den Weg zu PyCologne gefunden.

Python 2 oder 3? Natürlich 3. Migration: http://python-future.org/

- Ein guter Start, um die meisten Aspekte von Python kennenzulernen, ist das
  offizielle Python-Tutorial: https://docs.python.org/3/tutorial/
- Python-Module verwenden unterschiedliche Idiome, die teilweise nicht
  besonders "pythonisch" sind.
- Tutorials:
  - https://pythonprogramming.net/
  - https://biopython.org/
  - https://github.com/rbreu/python-course (von Rebecca, Mitglied der
    PyCologne)
- Ebenfalls empfehlenswert: einfach den Quellcode der Python-Distribution
  lesen.
- IPython und Jupyter-Notebooks als interaktive REPLs: http://jupyter.org/
- PyCharm ist eine einsteigerfreundliche IDE für Python.
- Für Kollaboration (aber auch nur für sich selbst) ist eine
  Versionsverwaltung (Git hat sich fast überall durchgesetzt) empfehlenswert.
- Einführung in Git mit Spielzeug: "git ages 4 and up":
  https://www.youtube.com/watch?v=3m7BgIvC-uQ
